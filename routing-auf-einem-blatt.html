-- kapitel --

1. Grundlagen klären

  • Routing: Weiterleitung von Paketen zwischen unterschiedlichen Netzen
  • Warum nötig: Innerhalb eines Netzes reicht Switching, netzübergreifend nicht
  • Gleiches Netz: direkte Zustellung über Switching/ARP, kein Router beteiligt
  • Fremdes Netz: Paket muss über einen Router weitergeleitet werden
  • Rolle des Routers: verbindet unterschiedliche Netze, trifft Weiterleitungsentscheidungen anhand der Zieladresse
  • Switch reicht nicht: arbeitet nur auf Schicht 2 (MAC-Adressen), kennt keine Netzgrenzen
Routing wird relevant, sobald Daten ein Subnetz verlassen und in ein anderes Netz weitergeleitet werden müssen.

2. Lokale Entscheidung des Hosts verstehen

  • Host führt ANDing durch: eigene IP + eigene Maske sowie Ziel-IP + eigene Maske
  • Ergebnis gleich -> Ziel im gleichen Netz -> direkte Zustellung (ARP-Auflösung)
  • Ergebnis unterschiedlich -> Ziel in fremdem Netz -> Paket geht an das Standardgateway
  • Standardgateway = Router-Interface im eigenen Netz, das den weiteren Weg übernimmt
Routing beginnt nicht erst am Router, sondern schon beim sendenden Host mit der Entscheidung "lokal zustellen oder an Gateway übergeben".

3. ANDing einordnen

  • ANDing: logische UND-Verknüpfung, bitweise zwischen IP-Adresse und Subnetzmaske
  • Ergebnis: die Netzwerkadresse
  • Zweck: feststellen, zu welchem Netz eine IP-Adresse gehört
  • Anwendung: wird auf Quell- und Ziel-IP angewendet, die resultierenden Netzwerkadressen werden verglichen
Nicht der Rechenweg zählt, sondern das Verständnis - ANDing dient dazu, Quell- und Zielnetz zu vergleichen.

4. Default Route verstehen

  • Default Route: Standardroute, greift, wenn kein genauerer Eintrag zum Ziel vorhanden ist
  • Auch "Gateway of Last Resort" genannt
  • Wird bei unbekanntem Zielnetz verwendet
  • Für Clients besonders wichtig, da sie meist nur ihr eigenes Netz plus Default Gateway kennen
Default Route = Auffangregel für alles, was sonst nicht bekannt ist.

5. Routing-Tabelle grob verstehen

  • Routing-Tabelle: Liste von Einträgen mit Zielnetz, Präfix/Subnetzmaske, Next Hop, ausgehendem Interface
  • Unverzichtbar für Router, da jede Weiterleitungsentscheidung darauf basiert
  • Auch normale Hosts besitzen eine einfache Routing-Tabelle (eigenes Netz + Default Route)
  • Mehrere mögliche Wege -> die spezifischere Route wird bevorzugt (siehe Punkt 9)

6. Static Routes

  • Statische Route: manuell eingetragener, fester Pfad zu einem Zielnetz
  • Vorteile: einfach, kontrollierbar, geringer Overhead (keine Protokoll-Last)
  • Nachteile: hoher Pflegeaufwand, wenig flexibel bei Änderungen
  • Funktioniert gut in kleinen/einfachen Netzen, wird in großen Umgebungen schnell aufwendig
Statische Routen sind einfach und kontrollierbar, aber nicht immer gut skalierbar.

7. Dynamic Routes

  • Dynamische Route: wird automatisch über ein Routing-Protokoll zwischen Routern ausgetauscht
  • Passt sich selbstständig an Netzänderungen an
  • Vorteile ggü. static: bessere Skalierbarkeit, weniger manueller Aufwand
  • Nachteile: höhere Komplexität, zusätzlicher Verwaltungs- und Verständnisaufwand

8. Static vs. Dynamic Routes vergleichen

KriteriumStatic RoutesDynamic Routes
Kontrolleleicht zu kontrollieren, vorhersehbarweniger direkte Kontrolle
Reaktion auf Änderungenkeine automatische Anpassungreagiert automatisch
Komplexitäteinfacherkomplexer (Protokoll verstehen und betreuen)
Overheadgering, keine Protokoll-LastRouter tauschen laufend Informationen aus

  • Vorteile static: leicht zu kontrollieren, vorhersehbar, geringer Overhead
  • Vorteile dynamic: reagiert automatisch auf Veränderungen, bessere Skalierbarkeit
  • Kleine/einfache Netze -> eher static; große/wachsende Netze -> eher dynamic
Kein Ansatz ist pauschal besser - es kommt auf Netzgröße und Anforderungen an.

9. Spezifischere Route gewinnt

  • Bei mehreren passenden Routen gewinnt die Route mit dem längeren Präfix (genauere Route)
  • Längeres Präfix = kleineres, genaueres Zielnetz
  • Wichtig z. B. wenn Default Route UND eine spezifische Route zum selben Ziel passen würden - die spezifische gewinnt
Router nehmen nicht "irgendeinen" Weg, sondern entscheiden anhand von Genauigkeit und festen Regeln.

10. Next Hop und Interface einordnen

  • Next Hop: IP-Adresse des nächsten Routers auf dem Weg zum Ziel
  • Ausgehendes Interface: Port, über den das Paket den Router verlässt
  • Kenntnis des Zielnetzes allein reicht nicht - der Router muss auch wissen, über welchen Nachbarn das Paket weitergeht

11. Typische Fehlerbilder grob einordnen

  • Falsches oder fehlendes Standardgateway
  • Fehlende Route zu einem Zielnetz
  • Falscher Next Hop
  • Statische Route falsch eingetragen
  • Rückweg fehlt
  • Netz ist bekannt, aber nicht erreichbar (z. B. Next Hop down)
  • Kommunikation funktioniert nur in eine Richtung (asymmetrisches Routing)

12. Routing in der Praxis bewusst wahrnehmen

  • Fast jedes größere Netzwerk ist auf Routing angewiesen (Trennung in Subnetze)
  • Viele Erreichbarkeitsprobleme hängen direkt oder indirekt mit Routing zusammen
  • Enger Zusammenhang zu IP-Adressierung und Subnetting - ohne sauberes Subnetting kein sauberes Routing
  • Sauberes Routing-Verständnis hilft bei Fehlersuche und Netzplanung

Wenn's hakt

ANDing-Rechnung unklar

Nicht am Rechenweg festbeißen, sondern auf den Zweck schauen: ANDing liefert die Netzwerkadresse, damit Quell- und Zielnetz verglichen werden können.

Static und Dynamic verwechselt

Eselsbrücke: Static = der Administrator trägt den Weg selbst ein (fest). Dynamic = die Router tauschen sich untereinander automatisch aus (beweglich).

Wann genau greift die Default Route?

Erst, wenn kein anderer, spezifischerer Eintrag in der Routing-Tabelle zum Zielnetz passt. Sie ist die letzte Instanz, nicht die erste Wahl.

Next Hop und Interface verwechselt

Next Hop = wohin (IP-Adresse des nächsten Routers). Interface = wodurch (die eigene Schnittstelle, über die das Paket den Router verlässt).
